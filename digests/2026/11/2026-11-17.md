- **公開日**: 2026-11-17
- **タグ**: `generative-ai` `machine-learning` `developer-tools`
- **一次情報**: [Microsoft AI公式発表](https://microsoft.ai/news/microsoft-ignite-2026/) / [model card](https://microsoft.ai/pdf/MAI-Code-2-And-MAI-Code-2-Flash-Model-Card.pdf?v=2)
- **日本語サマリ**: Microsoftはrepo全体の推論、deep debugging、multifile実装、UI生成を想定するMAI Code 2と、高頻度の説明・局所編集・routine fix向けCode 2 Flashを公開した。4つのcoding benchmark平均でCode 2はGPT-6.1 Solの98%の性能を40%の価格で、Opus 5.5の96%を5%の価格で達成したと報告。両modelはsparse MoEとvision encoderを備え、GitHub Copilotで提供される。
- **重要性・実務上の示唆**: 全taskをfrontier modelへ送らず、修正規模と難度に応じてflagship／Flashをroutingすることでagent codingのunit economicsを設計しやすい。評価ではPR merge率、revert率、review時間、test失敗、task当たり費用を自社repoで測る必要がある。
- **限界**: 性能比と価格比はMicrosoftの平均benchmarkで、repo・言語・tool harnessごとの差を含まない。提供元自身が基礎科学や非常に長いhorizonのagent taskには未調整と明記する。Foundryでの提供形態はmodelごとに異なり、Flashはlimited access previewを含む。

### 2. PreVAP：18変数のCatBoostで人工呼吸器関連肺炎を24時間前に予測

- **公開日**: 2026-11-17
- **タグ**: `data-science` `machine-learning` `business` `healthcare`
- **一次情報**: [Scientific Reports原論文](https://www.nature.com/articles/s41598-026-80526-w)
- **日本語サマリ**: 侵襲的人工呼吸を48時間以上受けた成人2,817人（VAP 334人）の2014〜2025年EHRを使い、12 algorithm、複数のfeature選択、1・24・48時間前の予測を比較した。最終CatBoostはroutine収集する18変数で、診断24時間前のheld-out testにおいてAUROC 0.86、sensitivity 0.76。SHAP説明付きriskを毎時出すdashboardをsilent modeで配備した。
- **重要性・実務上の示唆**: 早期介入、ICU在院日数、抗菌薬、合併症costへつながる可能性があり、単発scoreでなく時系列riskと説明・監査traceを現場workflowへ組み込んだ点が実装参考になる。次段階ではalert当たり介入率、false alert、lead time、抗菌薬使用、在院日数、clinical outcomeを測るべきである。
- **限界**: 単施設の後ろ向き研究で、外部・前向き検証は未実施。silent modeは臨床介入効果やcost削減を示さず、2014〜2025年の診療・data品質の変化も受ける。334 eventのclass imbalance、施設固有の診断・運用を踏まえ、閾値とcalibrationを移植先で再評価する必要がある。

### 1. remote coding agentへcredentialを渡さず、local実行を都度承認する「lend」

- **公開日**: 2026-11-13（2026-11-17更新）
- **タグ**: `developer-tools` `security` `agents` `infrastructure`
- **記事原文**: [Antonio Mikaの技術解説](https://blog.antonio.cx/running-agents-with-lend)
- **関連一次情報**: [antoniomika/lend](https://github.com/antoniomika/lend)
- **日本語サマリ**: remote VMのagentへGitHub tokenやSSH private keyを置かず、forwardしたSSH agent socket越しにlocal側の`gh`等を実行するproxyを解説する。local policyでexecutable、argument prefix、key fingerprint、回数・時間leaseを制限し、requestごとにTouch ID等で承認。secretはlocalで注入し、stdout・stderr・終了codeだけをremoteへ返す。
- **重要性・実務上の示唆**: agent identityをhuman credentialから分離できない環境でも、credential custody、allowlist、human approval、短期lease、audit historyを境界として設計する具体例である。agent用の短命・最小権限tokenを発行できる場合は、専用identityと併用する方が望ましい。
- **話題性**: [Hacker News個別thread](https://news.ycombinator.com/item?id=50526152)で121 points・98 commentsを確認。確認日: 2026-11-18 JST。
- **限界**: 承認したcommandはlocal user権限で動き、sandboxではない。shell、interpreter、stdinを許すと任意実行へ広がり、remoteが提示するcaller情報も偽装可能。early stageで、interactive PTYは非対応、biometric承認はmacOS中心である。

### 2. coding agentの検証loop：E2E・property・differential testを使い分ける

- **公開日**: 2026-11-16
- **タグ**: `developer-tools` `generative-ai` `software-engineering` `agents`
- **記事原文**: [claude.dev公式engineering blog](https://claude.dev/blog/how-the-claude-code-team-thinks-about-verification/)
- **日本語サマリ**: Claude Code teamは、実user flowを通すE2E、制約を大量入力で崩しに行くproperty test、旧新systemを同じ入力で比較するdifferential testをagent検証の中心に置く。diffに応じてreliability checkを選び、3回失敗後にhumanへ上げ、review ruleはbase branchから読み、commit単位で検証結果を固定する運用を説明した。
- **重要性・実務上の示唆**: agentの生成量を増やす前に、実行環境、acceptance criteria、改変できないgrader、失敗時escalation、revert由来の回帰ruleを整備すべきことを示す。PR数ではなく、stable merge、revert、incident、検証cost、human review時間をKPIにするのが実務的である。
- **話題性**: [Hacker News個別thread](https://news.ycombinator.com/item?id=50529612)で143 points・136 commentsを確認。確認日: 2026-11-18 JST。
- **限界**: codeの約90%をClaudeが書きreviewすることや、別graderでtask successが最大10 point改善したことは提供元の内部報告で、dataset・費用・再現手順は十分公開されていない。token予算、team規模、app種別が違う組織へ同じ運用を一般化できず、deterministic testで足りる箇所までmodel検証へ置き換えるとcostと非決定性が増える。

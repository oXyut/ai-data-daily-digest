## 1. GPT-6.1 Sol：エージェント作業向けモデルの更新

- **公開日:** 2026-09-29（OpenAIの[ニュース一覧](https://openai.com/news/)が個別発表の公開日を表示）
- **タグ:** `generative-ai` `llm` `developer-tools`
- **日本語サマリ:** OpenAIはGPT-6 Solの後継となるGPT-6.1 Solを発表。コーディング、PC操作、文書を使う業務での改善を報告し、APIの標準単価を入力100万トークン当たり2ドル、出力10ドル、キャッシュ入力0.10ドルとしました。APIでは `gpt-6.1-sol` として提供されます。
- **なぜ重要か:** エージェントに長い文脈を再利用させる設計では、キャッシュ単価とタスク完了までの費用がモデル選択に影響します。9/25号のGPT-6 Sol/Lunaとは別の、9/29付モデル更新です。
- **限界:** 「Astraに近い性能」などの比較と費用は提供元の評価条件によります。実業務での精度・費用を保証しません。ChatGPTの通常のChatでは発表時点で未提供と記載されています。
- **個別一次情報:** [OpenAI — Introducing GPT-6.1 Sol](https://openai.com/index/introducing-gpt-6-1-sol/)

## 2. OpenAI dots：継続的に作業するエージェント

- **公開日:** 2026-09-29（OpenAIの個別発表）
- **タグ:** `generative-ai` `agents` `developer-tools`
- **日本語サマリ:** OpenAIはGPT-6 Astraを使い、自身のクラウドコンピューターと接続アプリで継続的に作業する「dots」を発表。ChatGPT、Slack、Teamsから連絡でき、作業の確認やフィードバックができます。対象の市場・プランから段階的に提供を始めています。
- **なぜ重要か:** 単発の質問応答を超えて、継続案件の調査・更新・レビューをエージェントに任せる製品の提供開始です。作業状況と承認の設計が実務導入の焦点になります。
- **限界:** 発表にある請求書処理やコード修正は例示・初期利用者の事例で、一般的な成功率の証明ではありません。市場、プラン、管理者設定、接続アプリの権限によって利用範囲が異なります。
- **個別一次情報:** [OpenAI — Introducing dots](https://openai.com/index/introducing-dots/)

<a id="bigquery-key-drivers"></a>
## 3. BigQuery AI.KEY_DRIVERS：セグメント寄与分析がGA

- **公開日:** 2026-09-29（Google Cloudの公式リリースノート）
- **タグ:** `data-science` `data-engineering` `analytics`
- **日本語サマリ:** BigQueryの `AI.KEY_DRIVERS` 関数が一般提供になりました。関心対象と比較対象を示す列、合計可能な数値指標、ディメンション列を指定し、指標の変化に統計的に有意な寄与を示すセグメントをSQLで探索できます。モデルを別途作成・管理する必要はありません。
- **なぜ重要か:** 売上などの指標が変わった際に、どの地域・属性の組み合わせが変動に関係するかを、データ基盤上のSQLで絞り込めます。
- **限界:** 寄与セグメントは観測データの比較結果で、介入による因果効果を証明しません。対応する指標は合計可能なものに限られ、ディメンションは最大12列です。
- **個別一次情報:** [Google Cloud — 2026-09-29 release notes](https://docs.cloud.google.com/release-notes)、[BigQuery — AI.KEY_DRIVERS関数の仕様](https://docs.cloud.google.com/bigquery/docs/reference/standard-sql/bigqueryml-syntax-ai-key-drivers)

<a id="api-gateway-streaming"></a>
## 4. API Gateway：LLM応答などのストリーミングをプレビュー提供

- **公開日:** 2026-09-29（Google Cloudの公式リリースノート）
- **タグ:** `generative-ai` `data-engineering` `developer-tools`
- **日本語サマリ:** Google Cloud API Gatewayが、リクエスト・応答をバッファせず逐次転送できる機能をPublic Previewで追加。HTTPの分割転送、SSE、WebSockets、双方向gRPCを対象とし、LLMのトークン単位の応答も想定しています。新しいゲートウェイの作成時にストリーミングを有効化します。
- **なぜ重要か:** LLMアプリで回答全体を待たずに利用者へ途中結果を表示できます。既存APIの入口を使ったリアルタイム処理にも関わる更新です。
- **限界:** プレビュー機能です。ストリーミング設定はゲートウェイ作成後に変更できず、バックエンド側の対応と適切なタイムアウト設定も必要です。
- **個別一次情報:** [Google Cloud — 2026-09-29 release notes](https://docs.cloud.google.com/release-notes)、[API Gateway — ストリーミング設定](https://docs.cloud.google.com/api-gateway/docs/streaming-configure)
